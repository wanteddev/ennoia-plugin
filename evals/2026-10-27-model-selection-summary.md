# 모델 자동 선택 지침 비교

2026-10-27에 동일한 10개 합성 입력을 변경 전·후 각각 fresh context 5회로 평가했다. 기존 지침은 main `b1f6cc6`의 1.5.5이며 후보는 1.5.6이다. 모든 평가자는 동일한 상위 세션의 모델 설정을 상속했고 모델 override를 사용하지 않았다. 평가자는 build Skill과 필요한 내부 reference, 입력만 읽었으며 다른 평가 출력·rubric·diff는 제공하지 않았다. 최종 출력 후 작성자가 별도 rubric으로 다음 행동과 모델 선택을 확인했다.

| 관찰 경로 | 기존 5회 | 후보 5회 |
| --- | --- | --- |
| 모델군 첫 페이지에 구버전만 있고 다음 페이지가 남음 | 모두 `sonnet4-6`을 선택하고 추가 조회 생략 | 모두 같은 모델군의 `page=1`을 먼저 조회하고 선택 보류 |
| 기억한 구버전 exact 이름으로만 검색함 | 모두 `sonnet4-6`으로 선택 확정 | 모두 버전 없는 `query=sonnet`, `page=0`으로 재검색 |
| 현재 카탈로그 미조회 | 모두 현재 프로젝트 모델 조회 | 같은 경계 유지 |

개선으로 확인한 경로는 앞의 두 가지다. 기존에도 올바르게 처리한 8개 경로를 개선 실적으로 계산하지 않는다. 기존 평가에서 “충분한 자원을 찾으면 모든 페이지를 읽지 않는다”, “모델군 전체 비교 의무가 없다”는 이유로 구버전을 확정하는 행동을 확인했다. 후보는 관련 모델군의 최신 후보 확인을 완료 조건으로 삼고, 일반 자원 pagination 규칙과 모델 선택 기준을 연결했다.

입력 SHA-256은 `d0c1af26499651928ec5ae1f73228764f45a9151192349d477518d53f98b102d`다. 기존 build Skill은 `3ba79b76a1a2161a735c54395e865ba5502ab788e50468b10e1b84a7f34dc271`, 후보 build Skill은 `11a50397b4a4ba4b67b6299bfa2daa95f7035e53aaf3e020efabcee09fd0f82b`, 후보 모델 선택 reference는 `b26f2436bdd3ee6eda89f63e5dacc8ac26462657e9b2c37277810aad49d44e52`다. 원본 JSON 출력 10개와 기존 Skill 복사본은 Git 제외 로컬 `docs/model-selection-eval/`에 보관했다.

이 결과는 합성 입력에 대한 다음 의사결정 평가다. 다음 페이지의 실제 응답이나 실제 모델 실행·graph 검증·저장은 수행하지 않았으며, 가상 모델명·버전 관계는 실제 출시 정보의 증거가 아니다. 5회의 일치 결과를 통계적 성공률이나 모든 host에서의 동작 보장으로 해석하지 않는다. native 설치·새 세션 Skill 로딩·실제 MCP 업무는 별도 미검증 범위다.

패키지 검증·manifest sync·기존 결과 schema 검사, Python 회귀 63개와 Node 회귀 36개는 통과했다. 최초 시스템 Python 실행은 `jsonschema` 의존성 부재로 실패했으며, 저장소의 `requirements-dev.txt`를 별도 venv에 설치한 뒤 전체 검사를 통과했다.

Claude CLI의 Marketplace·Plugin `validate --strict`도 exit 0으로 통과했다. Plugin Directory 제출용 추가 진단에는 기존 LICENSE 부재와 privacy policy URL 부재가 표시됐다. 해당 Directory 제출 검사는 이번 모델 선택 변경 범위가 아니며, native 설치·OAuth·실행 성공의 증거로 사용하지 않는다.
