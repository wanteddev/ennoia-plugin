# 도구 발견 복구 합성 적용 평가

2026-11-12에 기존 Plugin `e063430` / 1.5.8과 후보 1.5.9의 Skill/reference를 같은 [6개 시나리오](tool-discovery-scenarios.json)로 비교했다. arm마다 별도 맥락의 sub-agent 5개가 다음 행동·보존할 대상과 ID·사용자 안내를 작성했다. 기대 rubric과 다른 arm의 응답은 생성 시 제공하지 않았고, 작성자가 [rubric](tool-discovery-rubric.md)으로 모든 응답을 수동 판정했다. 생성은 독립 표본이지만 판정은 arm을 아는 작성자의 판단이며 blind 평가가 아니다.

| 확인 항목 | 기존 지침 | 후보 지침 |
| --- | --- | --- |
| 부분 목록·reload·미완료 server page를 서버 미지원/복구 완료로 단정하지 않음 | 해당 3개 case × 5회 모두 준수 | 해당 3개 case × 5회 모두 준수 |
| 기존 테스트 조회 누락 시 복구 단계에 실제 서버 목록·revision 비교와 새 채팅 확인을 모두 명시 | 1/5회 | 5/5회 |
| 기존 테스트 ID·대상과 마지막 running 상태를 유지하고 새 start를 하지 않음 | 5/5회 | 5/5회 |
| 같은 revision의 전체 목록·새 채팅에도 없을 때 반복 갱신 중단 | 5/5회 | 5/5회 |
| 실제 401·ENNOIA_REAUTH_REQUIRED를 인증 복구로 구분 | 5/5회 | 5/5회 |

기존 테스트 조회 누락 case에서 기존 지침 3회는 재발견 뒤 조회 불가 제한으로 안내했고, 1회는 새 채팅까지 포함했으나 revision 비교가 없었다. 나머지 1회와 후보 5회는 두 단계를 모두 명시했다. 보강 효과는 이 복구 절차의 누락 감소로 한정한다. 기존 지침도 미지원 단정을 피한 사례를 새 개선으로 계산하지 않는다.

후보의 30개 응답에서 없는 host 명령·내부 API 발명, 자동 새 채팅 생성, credential 추출, 중복 테스트·배포·실행을 제안한 사례는 관측하지 못했다. 표본이 작고 합성 입력을 사용했으므로 실제 업무 성공률·성능 개선으로 일반화하지 않는다.

실제 Ennoia MCP·Backend 호출, OAuth·native 설치·새 채팅의 실제 목록 갱신은 이번 평가에서 실행하지 않았다. 이전 별도 Codex catalog 재현의 결과를 이 Plugin 수정의 검증 성과로 계산하지 않는다. 이 변경은 assistant의 발견·판단·복구 안내를 보강하며 Codex의 기존 채팅 catalog 자동 갱신을 구현하지 않는다.
