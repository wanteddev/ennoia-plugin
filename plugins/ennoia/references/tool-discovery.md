# 일부 Ennoia 도구가 보이지 않을 때

초기 노출 목록, host의 전체 inventory, 서버의 `tools/list`를 구분한다. 도구를 발견하지 못했다는 사실만으로 서버·backend 미지원이나 인증 만료를 확정하지 않는다. 필요한 도구 이름과 실제 사용 연결을 기준으로 다음 순서를 적용한다.

## 재발견과 연결 비교

1. host의 전체 Plugin·MCP server inventory에서 실제 Ennoia 연결 식별자를 확인한다. 이미 정확한 식별자가 있으면 재사용한다. host가 제공하는 전체 도구 목록 또는 deferred search에서 필요한 이름을 찾고 현재 연결의 input schema를 확인한다. Skill 이름·로컬 manifest 이름을 host의 설치 ID나 서버 이름으로 추측하지 않는다.
2. 계속 누락되면 실제 사용 연결의 endpoint와 initialize metadata의 `source_revision`을 확인한다. 같은 endpoint·인증 조건에서 수집한 서버 `tools/list`와 host 목록을 비교하며, `nextCursor`가 있으면 마지막 page까지 수집한다. host가 이 정보를 제공하지 않으면 확인할 수 없는 항목을 미확인으로 남긴다. 진단을 위해 credential을 추출하거나 사용자가 token을 복사하도록 요청하지 않는다.
3. 실제 revision이 다르면 연결별 목록 차이로 보고한다. Plugin 버전이 같아도 서버 revision이 같다는 뜻은 아니다. 다른 연결의 schema를 현재 연결에 적용하지 않으며, metadata가 없다는 이유로 같은 revision이라고 가정하지 않는다. 도구 이름이 같아도 backend API 배포·권한·업무 실행 성공은 별도 확인한다.
4. 서버 목록에는 있지만 현재 host에 없거나 연결 목록 차이가 있으면 host가 실제 제공하는 재발견·refresh/reconnect를 한 번 적용하고 필요한 도구와 revision을 다시 확인한다. **설정 reload 성공은 기존 채팅의 tool catalog 갱신 성공이 아니다.** 이미 수행했는데 목록이 그대로면 같은 작업을 반복하지 않는다. 없는 명령·도구나 내부 호출 API를 만들어내지 않는다.
5. 기존 채팅 목록이 유지되거나 갱신 기능이 없으면 새 채팅·MCP 연결에서 같은 대상의 필요한 도구와 실제 revision을 확인하도록 안내한다. 새 채팅에서 확인하기 전에는 복구됐다고 보고하지 않는다. 새 채팅에서도 미발견이면 확인한 범위와 남은 제한을 보고하고 무한 재연결하지 않는다. 진단을 위해 사용자의 기존 채팅을 삭제하거나 자동으로 새 채팅을 만들지 않는다.

## 관측에 따른 판단

| 관측 | 판단과 다음 행동 |
| --- | --- |
| 초기 노출·부분 inventory에만 없음 | 전체 발견과 필요한 도구 검색을 먼저 수행한다. 서버 미지원은 미확인이다. |
| 서버 목록에 다음 cursor가 남음 | 남은 page를 수집한다. 마지막 page의 cursor 부재만으로 전체 수집 완료라고 하지 않는다. |
| revision 차이 또는 서버에는 있고 host에는 없음 | 실제 연결 metadata를 대조하고 재발견·새 채팅 확인을 안내한다. host 내부 cache·filter 중 세부 원인은 별도 증거가 필요하다. |
| 재발견·새 연결까지 확인한 같은 revision의 전체 서버 목록에도 없음 | 해당 revision의 목록에 필요한 도구가 없다고 보고하고 현재 연결의 제한을 안내한다. 다른 revision·플랫폼 전체·backend 미지원으로 일반화하지 않는다. |
| 도구는 발견됐지만 실제 호출이 실패함 | 오류가 가리키는 대상·권한·API 계약을 확인한다. 404만으로 도구 목록이나 backend 미지원을 확정하지 않는다. |

실제 401·`AUTH_REQUIRED`·`ENNOIA_REAUTH_REQUIRED`는 [인증 복구](../skills/ennoia-connect/references/authentication.md)를 따른다. 403·권한 오류도 목록 누락과 구분한다. 누락만으로 재로그인·계정 전환·로그아웃·연결 삭제를 하지 않는다.

`CANONICAL_GRAPH_UNAVAILABLE(revision_not_supported)`는 전체 canonical graph 경로의 제한이다. 프롬프트·모델 설정 전용 도구의 부재나 미지원을 증명하지 않는다. 도구 발견을 확인하려고 graph 저장·테스트 시작·배포·실행·키 재발급을 하지 않는다.

## 기존 작업 이어가기

새 연결로 넘어갈 때 확인한 그룹·프로젝트, 에이전트 ID, stage·배포 버전, 기존 `test_id`·Trace ID·`operation_id`, 마지막 확인 상태와 승인 범위를 보존한다. 같은 테스트는 기존 ID 조회부터 이어가며 결과가 불명확한 실행을 새 ID로 다시 시작하지 않는다. 승인 범위가 같은 복구·조회마다 재승인을 요구하지 않는다. credential·인증 URL은 전달하지 않는다.

완료 안내는 **확인한 목록·연결 → 남은 제한 → 다음 확인 단계** 순서로 간결하게 쓴다. 예: “현재 채팅에는 조회 도구가 없고 설정 재로드 후에도 목록이 그대로입니다. 새 채팅에서 같은 프로젝트와 기존 테스트 ID로 조회 도구를 확인해야 하며, 테스트 결과는 아직 미확인입니다.”
