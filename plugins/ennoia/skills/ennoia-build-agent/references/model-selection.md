# 모델 선택 기준

새 agent의 모델을 자동으로 정할 때 적용한다. 각 역할의 업무 난이도·비용·필수 기능을 먼저 판단하고, 적합한 모델군·등급 안에서 현재 프로젝트가 제공하는 최신 버전을 선택한다. 최신이라는 이유로 더 비싼 등급으로 올리거나 필수 기능을 포기하지 않는다.

## 선택 순서

1. 사용자가 exact 모델·버전을 지정하면 그대로 사용한다. 모델군만 지정하고 버전을 맡겼다면 그 모델군의 최신 버전을 선택한다. 기존 graph의 모델은 변경 요청이 있을 때만 바꾼다. 이전 작업에서 사용한 모델은 새 agent의 고정 설정이 아니다.
2. 현재 작업에서 해당 project의 유효한 모델 목록을 확보하지 않았다면 `list_multi_agent_models`를 `page=0`부터 조회한다. query는 버전을 포함하지 않은 모델군 이름으로 좁힌다. 기억한 구버전의 exact 이름으로 검색한 결과만 있다면 모델군으로 다시 검색한다. 모델군이 아직 정해지지 않았다면 후보를 비교할 수 있는 범위로 조회한다.
3. 선택할 모델군의 결과에 `has_next=true`가 있으면 `next_page`를 따라 관련 후보를 모두 확인한 뒤 버전을 확정한다. 첫 번째 사용 가능 모델을 찾은 것은 최신 확인의 완료 조건이 아니다. 관련 없는 자원 목록까지 전부 조회하지 않는다.
4. 현재 discovery와 node schema로 필수 기능을 확인한다. RAG·image·document·구조화 출력 등 요구를 만족하는 후보끼리 비교한다. 지원 여부가 null/누락이면 지원한다고 단정하지 않는다. 최신 후보가 필수 기능이나 명시된 비용 한도를 충족하지 못하면 조건을 만족하는 최신 후보를 고르고 그 제약을 설명한다. 카탈로그에 없는 가격·속도·기능은 만들지 않는다.
5. 같은 provider·모델군·등급에서 확인 가능한 버전 의미로 최신을 판단한다. 명확한 숫자 버전은 major/minor 등을 숫자로 비교한다. 문자열 사전순·목록 순서·과거 성공 경험을 출시 순서로 취급하지 않는다. custom alias 등으로 버전 관계가 불명확하면 최신을 확정할 수 없다고 밝히고 선택에 필요한 정보만 확인한다.
6. `llmConfig.model`에는 반환된 exact `model_name`을 넣는다. 표시명·별칭·구분자를 임의 보정하거나 목록에 없는 최신 모델명을 합성하지 않는다. 최종 안내에는 선택 모델과 업무 적합성·최신 후보 판단 근거를 짧게 전달한다.

현재 프로젝트에 없는 공개 최신 모델을 사용할 수 있다고 가정하지 않는다. 지정 모델이 실행 불가하면 이유와 대안을 제시하고 사용자 선택을 받는다. 모델 선택 이후 graph 검증·테스트·저장은 기존 계약을 따른다.
